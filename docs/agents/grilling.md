# Grilling: 盘问式需求收敛

> 来源：mattpocock/skills 的 grilling + grill-with-docs（盘问同时产出文档）组合，线上版全文中文适配。作用：对计划、决策、需求进行持续盘问，直到达成共识、无静默假设。触发方式见文末。

## 方法论

对用户进行持续盘问，直到达成共同理解。把讨论映射为一棵**设计树**：每个决策分支出挂在它下面的子决策。

按**轮次**推进。**前沿（frontier）**= 所有前提条件已经确定的决策：即此刻可以提出、无需猜测未得到答案的问题。每轮一次问完整个前沿：给每个问题编号，并给出你的推荐答案。等用户回答后再进入下一轮。

每轮的格式如下：

```
❓ **Q1** - **<问题标题>**: <问题正文，可以多段，包含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文，可以多段，包含多个选项>

➡️ <你的推荐答案>
```

每轮用户的回答都会重塑设计树：已确定的决策把前沿向外推进，解锁依赖它们的问题。重新计算前沿，进入下一轮。一个问题的答案若依赖本轮尚未关闭的另一个问题，它属于**之后**的轮次，不属于本轮。

查找**事实**是你的职责，永远不是用户的。当前沿问题需要环境中的事实（文件系统、工具等）时，派一个子 agent 去查；任何你能自己查到的东西都不要问用户。不要阻塞：一个进行中的探查只是一个未决前提，只有它下游的问题等待子 agent 回报，前沿的其余问题现在照问。**决策**是用户的：把每个决策摆给用户，然后等待。

会话结束条件：前沿为空——设计树的每个分支都已访问，没有任何静默假设。在用户确认你们已达成共识之前，不要采取行动。

## 盘问与文档产出

盘问不是停留在对话里的过程，而是边盘问边把结果落进仓库文档（grill-with-docs 约定）：

```
盘问进行中 ──┬── 每轮用户确认的决策 ──────→ spec.md（追加）
             ├── 出现的新领域术语 ────────→ CONTEXT.md 词汇表
             ├── 定下的重大架构决策 ──────→ docs/adr/（新 ADR）
             └── 依赖外部条件的 open question → .scratch/ 对应目录
盘问结束（前沿空 + 用户确认共识）→ spec.md 升格为施工定稿依据
```

- **盘问对象**：`spec.md` 需求记录、`framework-selection.md` 选型、任何计划或设计草案。
- **与需求记录的关系**：`spec.md` 定位为「会变动的需求记录」，grilling 就是控制变动的机制——用盘问让需求在动手前收敛，而不是写死一份完美需求。
- **与领域文档的关系**：术语与决策的产出遵循 `docs/agents/domain.md` 约定（单上下文：CONTEXT.md + docs/adr/）。

## 触发方式

用户说「grill」「盘问」，或要求「拷问我的计划/需求/决策」时，agent 阅读本文档执行。盘问未结束（前沿非空）时，不进入任何实现工作。
