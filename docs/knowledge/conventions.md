# 工程执行规范与决策原则

## 工程决策原则

一切选型与工程决策兼顾「成品可展示」与「方法论可沉淀」——仓库整体是交付物，决策与过程记录须经得起公开评审；文档措辞公开中立，不落个人敏感意图，需要表达时一律用「可展示性/公开评审」表述。

## 工程执行规范

- **验收标准必须可验证**：spec/issue 中每个任务的验收标准落到具体文件、具体函数、具体测试——不接受「实现某功能」式模糊描述
- **完成标准**：标记任务完成前必须——相关测试全部通过；git diff 覆盖验收标准的全部条目；无 TODO/FIXME/HACK 等未完成标记
- **反虚构**：遇到不确定的实现细节，先查文档再编码，不猜测；知识实时性优先于模型记忆
- **API 契约优先**：涉及前后端协作的任务，spec 阶段必须确定 API/事件契约（路径、请求/响应格式），前端基于契约开发，不等待后端完成
